# VDD Implementation Specification for Code Agent (v5.0)

**Document version**: v5.0 (minimal tool set)
**Target**: Refactor VDD MCP server into a stateless, Skills-over-MCP architecture with enforced bidirectional completeness.
**Protocol baseline**: MCP 2026-07-28 
**Skill format**: Agent Skills specification 
**Skills extension**: SEP-2640 (`skills/list`, `skills/get`, `skill://` resources) 

**Key change from v4.0**: The 10 tools are consolidated into **3 tools** (`vdd_check`, `vdd_chain_validate`, `vdd_amend`) via a static phase dispatch table. All invariants (A/B/C) are preserved unchanged.

---

## 1. Architectural Invariants (Non-Negotiable)

Every artifact graph produced by VDD **MUST** satisfy these three invariants at every phase transition. A `vdd_check` call returns `PASS` **only if all three hold simultaneously**.

**Invariant A — Forward Completeness**: For every parent node `P` at phase N, at least one child at phase N+1 declares `serves == P.id`.

**Invariant B — Backward Soundness**: For every child node `C` at phase N+1, `C.serves` references an existing node at phase N. No orphans.

**Invariant C — Dedicated Chain**: For every parent `P`, at least one child exists whose `serves` value equals `P.id` **and is not shared by any other parent**. This is the structural fix for the "A-001-only" failure mode.

**Enforcement mechanism**: The tool builds a **coverage matrix** `M[parent_id][child_id] ∈ {0,1}` from the artifact text. PASS requires:
- `M` has no all-zero row (A)
- `M` has no all-zero column (B)
- For every row, at least one column with value 1 has column-sum exactly 1 (C)

## 2. MCP Server Specification

### 2.1 Transport and State

| Property | Requirement |
|---|---|
| Transport | **Streamable HTTP** only (`POST /api/mcp`). HTTP+SSE is deprecated . |
| State | **Fully stateless**. No `initialize` handshake. No `Mcp-Session-Id` . |
| Request metadata | Every request carries `_meta.io.modelcontextprotocol/{protocolVersion, clientInfo, clientCapabilities}` . |
| Discovery | Server **MUST** implement `server/discover` to advertise protocol versions and capabilities . |
| Version negotiation | On mismatch, return `UnsupportedProtocolVersionError` with `data.supported` . |

### 2.2 Tool Set (3 tools total)

All tools declare `annotations: {readOnlyHint: true, destructiveHint: false, idempotentHint: true}`.

| # | Tool | Input | Output |
|---|---|---|---|
| 1 | `vdd_check` | `{phase, content, declaredCounts, priorArtifacts?, codebaseAudit?}` | `{status, reasons, coverage}` |
| 2 | `vdd_chain_validate` | `{artifacts, declaredCounts}` | `{status, reasons, coverage}` |
| 3 | `vdd_amend` | `{content, declaredCounts, priorArtifacts, changeDescription}` | `{status, reasons, impactedArtifacts}` |

**Backward compatibility**: Old tool names (`vdd_vision_check`, `vdd_tactics_check`, etc.) are aliased to `vdd_check` with a fixed `phase` for one release cycle.

### 2.3 `vdd_check` — Unified Phase Validator

#### Phase Dispatch Table

### 2.4 `vdd_chain_validate` — Full-Chain Validator

Accepts all artifacts at once. Runs Invariants A/B/C across **every** phase transition and the full chain from `V-*` to leaf commits.

```json
{
  "type": "object",
  "properties": {
    "artifacts": {
      "type": "object",
      "properties": {
        "vision": { "type": "string" },
        "strategy": { "type": "string" },
        "tactics": { "type": "string" },
        "specs": { "type": "string" },
        "plan": { "type": "string" },
        "tasks": { "type": "string" },
        "validate": { "type": "string" }
      },
      "required": ["vision","strategy","tactics","specs","plan","tasks"]
    },
    "declaredCounts": { "type": "object" }
  },
  "required": ["artifacts", "declaredCounts"]
}
```

**Behavior**: Runs `vdd_check` logic for every phase present, aggregates results, then runs a cross-phase check that every `V-*` has a dedicated descendant chain reaching `TK-*`.

### 2.5 `vdd_amend` — Cascade Impact Analyzer

Accepts a changed artifact and returns which downstream artifacts are now invalid.

```json
{
  "type": "object",
  "properties": {
    "content": { "type": "string", "description": "The changed artifact text" },
    "declaredCounts": { "type": "object" },
    "priorArtifacts": { "type": "object", "additionalProperties": { "type": "string" } },
    "changeDescription": { "type": "string" }
  },
  "required": ["content","declaredCounts","priorArtifacts","changeDescription"]
}
```

**Output** adds:
```json
{
  "impactedArtifacts": {
    "type": "array",
    "items": {
      "type": "object",
      "properties": {
        "phase": { "type": "string" },
        "reason": { "type": "string" }
      }
    }
  }
}
```

**Behavior**: Parses the changed artifact's IDs, compares against `priorArtifacts` IDs, and returns every downstream phase whose `serves_*` references a now-removed or now-changed ID.

### 2.6 Implementation Notes (TypeScript)

- Use `@modelcontextprotocol/sdk` v1.7.0+ with `Stateless: true`.
- Implement `server/discover` returning `{supportedVersions: ["2026-07-28"], capabilities: {tools:{}, resources:{}, extensions:{skills:{}}}}`.
- **ID regex patterns**:
  - Vision goals: `/^V-\d{3}\b/`
  - Strategy pillars: `/^S-\d{3}\b/`
  - Tactics actions: `/^A-\d{3}\b/`
  - Specs: `/^SP-\d{3}\b/`
  - Plan components: `/^PL-\d{3}\b/`
  - Tasks: `/^TK-\d{3}\b/`
- **`serves` field extraction**: `/serves_(goal|pillar|action|spec|component):\s*(V|S|A|SP|PL)-\d{3}/g`
- **Dedicated check**: For row `P`, collect children where `M[P][C]=1`. Compute column sums. Dedicated exists iff ≥1 child has column sum == 1.


### 3.4 SKILL.md Body Template (all 9 skills)

```markdown
# VDD: {Phase Name}

## Step 0 — Declare counts
Read `priorArtifacts.{prior_phase}`. Extract all parent IDs.
Set `declaredCounts.{current} = {minimum_count}` (may be larger).
State: "I will generate at least {minimum_count} {items}, with one dedicated to each parent."

## Step 1 — Generate
For EACH parent ID in ascending order:
  Generate ≥1 child with `serves_{parent_type}: {parent_id}`.
  The FIRST child for each parent MUST serve only that parent.

## Step 2 — Self-verify before submit
Build matrix locally. For every parent:
  - Assert ≥1 child exists (Invariant A)
  - Assert ≥1 child serves only this parent (Invariant C)
If any assertion fails, regenerate before calling the tool.

## Step 3 — Submit
Call `vdd_check` with:
{ phase: "{phase}", content, declaredCounts, priorArtifacts: { ... } }

## Step 4 — Handle result
- `status == "PASS"` → proceed to VDD:{next_phase} skill
- `status == "FAIL"` → read `coverage.matrix`. For each empty row, generate
  the missing dedicated child. Re-submit (max 3 retries).
- After 3 FAIL → surface `reasons` to user and stop.

## Gate Criteria
{phase-specific gate dimensions}
```

## 4. Per-Phase Gate Specifications (Dispatched by `phase`)

### 4.1 `phase: "constitution"`

**Parents**: none. **Children**: 9 artifact names.

| Check | Failure reason |
|---|---|
| All 9 artifact names present | `"Missing artifact name: tactics"` |
| `declaredCounts` present | `"declaredCounts required"` |

### 4.2 `phase: "vision"`

**Children**: `V-001…V-00N`. **Minimum**: N ≥ 3.

| Check | Failure reason |
|---|---|
| Each goal has numeric metric | `"V-002 has no numeric metric"` |
| Non-goals non-empty | `"Non-goals section is empty"` |
| `declaredCounts.goals == N` | `"declared 3, actual 2"` |

### 4.3 `phase: "strategy"`

**Parents**: `V-*` from `priorArtifacts.vision`. **Children**: `S-*`.

| Invariant | Check |
|---|---|
| A | Every `V-*` has ≥1 `S-*` with `serves_goal == V-*` |
| B | Every `S-*` `serves_goal` exists in vision |
| C | For every `V-*`, ≥1 `S-*` serves **only** it |
| Count | `declaredCounts.pillars >= declaredCounts.goals` |

**Failure example**: `"V-002 has no dedicated pillar; S-003 serves V-001 and V-002"`

### 4.4 `phase: "tactics"`

**Parents**: `S-*`. **Children**: `A-*`.

| Invariant | Check |
|---|---|
| A | Every `S-*` has ≥1 `A-*` |
| B | Every `A-*` `serves_pillar` exists |
| C | For every `S-*`, ≥1 `A-*` serves only it |
| Count | `declaredCounts.actions >= declaredCounts.pillars` |

**Critical failure (the A-001-only case)**:
```json
{
  "status": "FAIL",
  "reasons": ["S-002 has no action item", "S-003 has no action item", "action_count=1 < pillar_count=3"],
  "coverage": {
    "forward_covered": ["S-001"],
    "dedicated": ["S-001"],
    "matrix": {"S-001": ["A-001"], "S-002": [], "S-003": []}
  }
}
```

### 4.5 `phase: "specs"`

**Parents**: `A-*` with `priority == MUST`. **Children**: `SP-*`.

| Invariant | Check |
|---|---|
| A | Every MUST `A-*` has ≥1 `SP-*` |
| B | Every `SP-*` `serves_action` exists and is MUST |
| C | For every MUST `A-*`, ≥1 `SP-*` serves only it |
| Count | `declaredCounts.specs == count(MUST actions)` |

### 4.6 `phase: "plan"`

**Parents**: `SP-*`. **Children**: `PL-*`.

| Invariant | Check |
|---|---|
| A | Every `SP-*` has ≥1 `PL-*` |
| B | Every `PL-*` `serves_spec` exists |
| C | For every `SP-*`, ≥1 `PL-*` serves only it |
| Count | `declaredCounts.components >= declaredCounts.specs` |
| DAG | Dependency graph acyclic |

### 4.7 `phase: "tasks"`

**Parents**: `PL-*`. **Children**: `TK-*`.

| Invariant | Check |
|---|---|
| A | Every `PL-*` has ≥1 `TK-*` |
| B | Every `TK-*` `serves_component` exists |
| C | For every `PL-*`, ≥1 `TK-*` serves only it |
| Count | `declaredCounts.tasks >= declaredCounts.components` |

### 4.8 `phase: "validate"`

**Parents**: all `V-*`. **Children**: commits from `codebaseAudit`.

| Invariant | Check |
|---|---|
| A | Every `V-*` has ≥1 verified descendant (commit + passing test) |
| B | Every commit traces to a `TK-*` that traces to a `V-*` |
| C | Every `V-*` has its own distinct descendant chain |
| Count | `completed_tasks == declaredCounts.tasks` |
